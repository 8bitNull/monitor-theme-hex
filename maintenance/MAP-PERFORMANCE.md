# 地图性能与部署说明

首页地图使用随主题分发的 SVG 世界轮廓，不依赖第三方地图瓦片服务。电脑默认显示，手机隐藏。地图用于地区筛选，不表示机房精确坐标。

## 为什么曾经出现灰色区域

原实现要等节点接口返回后才开始下载地图，同时还会预加载详情页。地图模块包含原始地理数据，并在浏览器里转换拓扑、计算投影及生成路径；后续节点更新和拖动又会触发额外工作。加载占位没有提示、超时或错误入口，所以下载慢、执行慢和加载失败看起来都是一整块灰色。代码能确认这些风险，但仅凭截图不能确定当时是哪一项触发，仍需现场网络与控制台记录。

## 现在的处理方式

- 首页根据屏幕与设置提前加载地图，与节点接口并行；详情页预加载延后到地图就绪后的空闲时段。手机、关闭地图和直接打开详情页不请求地图模块。
- 构建时完成投影、路径简化和地区坐标计算。浏览器直接读取生成的路径，不再携带原始拓扑及转换库。
- 地图只订阅节点名称、地区和在线状态。CPU、流量等读数变化不改动地图路径。拖动按动画帧合并更新，底图元素复用。
- 加载中、加载较慢和失败有不同提示。3 秒提示慢，15 秒提供恢复操作；迟到的成功结果仍可自动恢复。重试有明确入口，不循环刷请求。浏览器缓存了模块失败时，可用刷新页面恢复。
- 地图错误被限制在地图区域，地区筛选、卡片和表格入口继续可用。加载前后地图自身保持 310px 高度，全屏保留视图切换。

## 如何复测

安装依赖并执行 `npm run build`，地图数据会自动重建。`npm run demo` 提供演示服务；`node scripts/benchmark-map.mjs after` 测量 20、100、500 个节点，每组运行三次，结果写入 `tests/artifacts/map-performance/`。需要 Chrome。

基准使用相同电脑、1440×1000 视口、4 倍 CPU 降速和本地接口。ready 是导航至测试观察到地图可见的整页耗时，包含节点列表渲染，不是地图独立执行时间。拖动的 P95 帧间隔也受整页负载影响。longTasks 统计整个页面，不能全部归因于地图。样本较少，数据用于回归比较，不是所有设备的承诺。

原始结果保存在 `benchmarks/map/`。默认视角和最大 600% 缩放的对照图保存在 `screenshots/map-optimization/`。简化容差为投影坐标 0.25，加上坐标舍入；在当前截图条件下，与原始路径比较，默认视角和最大缩放中 RGB 最大通道差超过 20 的像素分别约占 0.003% 和 0.008%。小地区仍有独立点击标记。

## 服务器需要配合的设置

主题安装包不能替服务器修改 HTTP 响应头。建议在实际静态资源服务或反向代理上做到：

- 对 JavaScript、CSS、JSON、SVG 启用 Brotli 或 gzip，并正确返回 `Content-Encoding` 和 `Vary: Accept-Encoding`。
- 仅对带内容哈希的静态资源使用 `Cache-Control: public, max-age=31536000, immutable`。
- HTML 使用 `no-cache`，允许重新验证；API 沿用业务缓存策略，不能套用静态资源的一年缓存。
- 更新时先上传新资源再切换 HTML，并保留旧哈希资源一段时间，避免打开旧页面的用户遇到 404。发布异常时回退上一版本安装包。

执行 `node scripts/check-map-delivery.mjs https://你的站点/` 可读取首页、入口模块和地图模块的实际状态、压缩及缓存响应头，生成 `map-delivery-audit.json`。脚本输出供核对，不会修改服务器。未提供生产站点地址及部署配置，因此本次没有声称完成线上响应头验收。

本地传输验收可用 `THEME_DEMO_HTTP_CACHE=1` 和 `THEME_DEMO_PORT=4176` 启动演示服务，再执行 `node scripts/benchmark-map-delivery.mjs`。该脚本使用 1.6Mbps、150ms 延迟、4 倍 CPU 降速及真实浏览器缓存，分别测试三次冷、热加载。本地缓存模拟仅用于验收，不会被打入主题运行代码。

## 验收范围与边界

自动化覆盖慢节点接口、慢地图、404、超时后恢复、失败后的刷新恢复、手机与关闭地图不下载、实时数据更新、地区筛选和视图切换。完整浏览器回归另覆盖明暗主题、桌面与手机布局、详情和地图交互。

本次解决地图本身的下载与重复计算，并保留完整世界轮廓。500 个卡片的整页渲染依然有开销，4 倍 CPU 降速下不能保证每帧 16.7ms；如实际站点长期展示数百张卡片，下一步应单独评估卡片虚拟化，避免把整页成本误认为地图仍在重新计算。

## 本次实测结果

地图模块原始体积从 787,798 字节降至 271,631 字节；用同一 Node gzip 默认设置压缩，从 246,145 字节降至 96,559 字节，减少约 60.8%。与构建器显示的 gzip 数值可能略有差异，比较采用同一口径。

以下均为三次测试中位数；耗时单位为毫秒。

| 节点数 | 地图可见：优化前 → 后 | 拖动 P95 帧间隔：前 → 后 | 整页长任务数：前 → 后 |
|---|---:|---:|---:|
| 20 | 2607.1 → 1091.0 | 189.0 → 5.7 | 53.0 → 5.0 |
| 100 | 3663.6 → 1823.6 | 189.0 → 16.7 | 54.0 → 7.0 |
| 500 | 8278.5 → 8474.0 | 211.2 → 49.9 | 81.0 → 31.0 |

500 节点的首次可见中位数增加约 2.4%，三次结果波动较大，因此不能宣称该场景首屏更快。地图请求启动已从约 2.23 秒提前到约 0.31 秒，拖动显著改善，但整页卡片渲染仍是后续优化重点。20 节点帧间隔低于 16.7ms 与测试机器高刷新率有关，不代表普通 60Hz 屏幕能显示更多帧。

在六节点演示页的慢网传输测试中，冷加载可见时间中位数为 3.21 秒，热加载为 1.85 秒。三次热加载地图资源 transferSize 均为 0，验证了本地浏览器缓存复用；这些值不代表生产站点实测。
